# Codebase review — October 2026

Method: three read-only passes (backend/data, frontend/map/UX, security) over `NextJS/`. Static reading only; nothing was run dynamically except lint, `tsc` and `next build` (all pass). Items marked *(inference)* were not confirmed by running the code.

## Verdict
The idea and the thin route/controller structure are worth keeping. Almost everything else needs replacing: the data model cannot express the product (street naming), the write API is open to anyone, the map flow works only for an exact 7 m click, and the UI is the Cruip template with English-only copy.

## Backend and data
- `Address` has no 2dsphere index; `createIndexes` is called per request, unawaited and malformed, so nearby lookup fails (`address_controller.js:49`). Error is returned as status 510.
- Every field is `required` **and** has a default, so validation never fails; missing coordinates silently become `[0,0]` (`addressModel.js:12`).
- Controllers read `street`, which is not in the schema: silently dropped (`address_controller.js:112,172`).
- `add_address` leaves `name` as "Unnamed", so those rows are hidden by name search (`address_controller.js:94`).
- `PUT`/`DELETE` skip `connectToDatabase()`; `GET` on mailing/addrequest/add_address returns undefined (500); not-found returns 500; create in `add_address` returns 200.
- `Request` stores the street as one free string with no coordinates and no link to an address. **No entity represents a street**, so "first registrant names the street" is impossible today.
- Dead code: `add_ask_controller.js:46-113`, `request_controller.js:41-108` (references an undefined `Address`), `deletefromMailing`.
- Keep: route/controller split, GeoJSON-style address shape, `$geoNear` approach, `addrStatus` as a moderation hook, cached connection.

## Frontend, map and UX
- Flow today: landing -> map -> click -> "Add it" (full page reload) -> 6-field form -> alert. A separate request form. No confirmation, no share, no way back to your address.
- Auth pages (signin/signup/reset) do nothing; the submit sends email and password in the URL (`signin/page.tsx:21,39`). Google buttons are dead. Footer links, privacy links `#`, testimonials, fake price/time promises ("from 1000 FCFA", "less than 24 hours"): template leftovers. `testimonials.tsx`, `blocks.tsx` are unused.
- English only, `lang="en"`, "Create Next App" metadata, Cameroon never named. Jargon: "Localization", "Choose WISELY".
- Map: Mapbox GL + geocoder + directions plugin. Starts over New York then flies to Yaoundé at 0.4 speed (`map.tsx:28,318`). 100vh plus padding overflows on phones (`map/page.tsx:12`). "Add it" button is 20 px tall (`map.tsx:193`). Geocoder + Anzi API queried on every keystroke without debounce. Query not URL-encoded (`map.tsx:262`). Directions are a custom Mapbox UI at 12 px text; `@mapbox/mapbox-gl-directions` also breaks `npm ci` (peer `mapbox-gl <2`).
- Click model: nearest Anzi point within 7 m, popup only inside a hard-coded Cameroon box (`map.tsx:238`). Real GPS error is usually larger than 7 m, so lookups will mostly miss.
- No Google Maps handoff at all.
- Performance: ~5 MB images + 2.7 MB unused video in `public/`; landing loads about 2.8 MB of images; whole `(default)` layout is a client component; AOS re-inits every render; Mega/Mediafire iframe for the hero video.
- Tailwind config defines `brown` twice, so the palette is partly lost. Contrast failures (gray-500 and brown-600 on the dark background, about 4.2:1 and 3.5:1, own calculation).
- Keep: sensible Yaoundé default, geolocation control, accessible mobile menu, self-hosted fonts, AOS disabled on phones, `next/image`.
